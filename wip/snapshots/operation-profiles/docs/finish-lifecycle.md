# Verified finish and explicit retention

`finish` defaults to destruction after the current final S3 snapshot passes the existing manifest/SHA/readback/attempt/activity gate. It is an explicit finish operation, not idle/orphan reclamation. An ordinary task exit, driver failure, raw Nomad stop or garbage collection without this bound intent retains the disk. No existing stopped VM is retroactively selected for deletion.

The plugin first uses native allocation exec to preflight `finish-v1` while the runtime is still ready. It prepares/verifies guest files and closes the ACP session, then binds the exact request/snapshot/manifest and S3 receipt hashes using the same authenticated Nomad API. The driver verifies allocation, worker session, creator metadata generation, task/spec and current machine/boot identity under the exclusive operation lock. It records schema4 and fences new exec activity and secret redelivery. It does **not** independently contact S3: storage durability is verified by the plugin, whose existing authorized allocation-exec caller asserts the receipt. Guest stdout and guest-written finish markers cannot arm host deletion.

The normal Nomad stop path stops the runtime, confirms task-token revocation and owned VM stopped/no reported PIDs, verifies disk identity, writes/fsyncs the existing purge-intent audit and deletes exactly that Lima instance without force. Only fresh instance/directory absence plus durable completion audit release the retained disk reservation. The existing purge audit format is reused. A lost deletion response retains the reservation; a later same-task absence reconciliation does not repeat delete. Unknown/present/mismatched instances never release quota. A completed tombstone can recover without VM recreation or credential injection.

The plugin requires the matching `vm_disk_purged` event (manifest/request/snapshot/audit), then returns `finished_destroyed`, `disk_purge_requested: true`, `quota_released: true`. A missing observation remains unconfirmed; do not assert that the disk is present or absent from caller timeout alone. Exported results remain usable after VM destruction.

`finish --retain-for resume|template|debug` explicitly retains the disk and returns `nomad_terminal` with the reason. Template source-finalization invokes `--retain-for template` internally. Existing in-flight legacy closing records without a cleanup policy continue retaining; the upgrade never converts them to deletion. Coordinator-local-only output cannot authorize default destruction; use a verified S3 export or explicit retention.

This release changes driver and caller, but no baked guest asset. Install/review the new driver before using the new default finish. Old drivers refuse preflight before runtime close. Once schema4 exists, do not downgrade to an older driver. Keep live bindings, existing disks and owner records intact during rollout. Acceptance still requires independent review and an isolated no-model S3→finish→absence/quota canary before production activation. No live cleanup is implied by the source release.
