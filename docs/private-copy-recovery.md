# Operator-pinned recovery copy

This is a one-off recovery input, **not** an accepted reusable template and not adoption of the old instance. Original ledger, disk, workspace, git and tracker remain intact. The pinned staged input also remains immutable. New allocation/session/VM, reservations and task-scoped Vault token use the normal driver and ACP path. No project command or prompt is replayed.

1. Operator prepares/checks a standalone qcow2 copy of the physically stopped original and records exact source key, owner, allocation/session, disk SHA/size and native initiator generation. `tools/prepare-private-copy-inputs.py --prepared-observation OBSERVATION --node-id NODE_UUID --namespace NAMESPACE --max-reserved-disk-gib CAP --output PRIVATE.config` converts the approved prepared-copy report. It never reads credentials, creates a VM or submits a job. Architecture is amd64 for this bounded legacy import tool. The driver manifest accepts amd64/arm64 explicitly.
2. Install the **same SHA-pinned bytes** root:root0600 on the source node using operator-controlled installation tooling (`.config`, outside the ledger JSON glob). Driver fields: `private_copies_file`, `private_copies_sha256`. Caller private config references its own owned0600 copy using those same keys. No disk URLs/paths are supplied by the agent. Existing configured node disk cap must cover the manifest cap; no cap is raised by this mechanism.
3. From the actual still-active initiating native session: `nomad-workers --config CONFIG recover-copy --input-id ID --session NEW_UUID --creator-record REAL_RECORD --vcpus N --memory-mib M`. The command persists intent **before** submission; interrupted/unknown submission is lookup-only with the same session. `request-status` → normal `create` once → status/session-ready. It returns source provenance as `recovery_parent`, never claims legacy StopReceipt or sealed/two-boot catalog acceptance. Both IDs remain discoverable in the durable intent/target.
4. Before create, driver rechecks original ledger/ownership, physical stopped/no PIDs, original and staged copy SHA/size, standalone qcow2 header, exact node/namespace/owner/generation and resource bounds under the existing reservation lock. Input/source may be claimed once. Staged copy is materialized through the existing immutable local image cache with normal no-mount/no-agent-forwarding YAML.
5. Before any new token/workload, one-shot root preparation inside the **new writable guest only** removes the entire reserved `/var/tmp/nomad-workers` runtime root (after non-overlap/symlink checks against workspace), and known Prime/acpx/Bao token/config locations, resets cloud-init machine/SSH-host identity and random seed. Workspace/git/tracker/package installation are preserved. A private fsynced proof binds new session + source/copy/manifest. Controlled stop/start must produce new machine and boot IDs before ordinary token injection/ACP bootstrap. Unexpected existing runtime processes, symlinks, cleanup/reboot uncertainty fail closed and retain the new disk. Recovery after lost cleanup response uses proof-only probe, never blind cleanup replay. No arbitrary file scan or package reinstall.

The original remains stopped and retained; this operation does not release its reservation. New schema3 ledger snapshots the approved input so config rotation cannot reselect it. Older schema1/2-only drivers must not replace this binary once schema3 exists. A future normal receipt-backed resume preserves this recovery provenance; it does not import legacy history. Operator inspection is required for an uncertain pre-token bootstrap; no automatic new request/input reset is provided.

Acceptance before user recovery: independent source review, exact Ansible config validation/staging, one owned disposable copy bootstrap including cloud-init reboot, token/ACP checks (no model), then each explicit prepared input. Offline tests cannot establish actual guest cloud-init or live ACP readiness. No runtime activation was performed by this source change.
